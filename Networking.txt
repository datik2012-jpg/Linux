When we done with configuration run:
>sudo netplan try
>ip route - check the routes

	
Those two lines define the DNS servers your system will use for name resolution. They tell Netplan to configure the interface to use 8.8.8.8 and 8.8.4.4 as DNS servers.	
Netplan writes these DNS servers into the backend resolver. You can verify with:
>resolvectl status
or check /etc/resolv.conf depending on your system. 


This means:

The destination network is 192.168.0.0/24  
(all IPs from 192.168.0.1 to 192.168.0.254)

To reach that network, your machine should send packets to the gateway 10.0.0.100.

In other words:

“If you want to reach any device in 192.168.0.x, forward the traffic to 10.0.0.100.”

This is a static route—useful when that network is behind another router.

- to: default
  via: 10.0.0.1
  
  is defines the default gateway.

to: default means “all traffic that doesn’t match any other route.”

via: 10.0.0.1 means “send it to 10.0.0.1.”

This is your internet gateway.

So:

“For everything else (web browsing, external networks), send traffic to 10.0.0.1.”


Destination	How traffic is routed
192.168.0.0/24	Forward to 10.0.0.100
Anything else	Forward to 10.0.0.1 (default route)

/////////////////Bridge and Bonding /////////


Bonding - when 2  enterfaces cards connected to the same network ( good for availability) if one of them fails second still working

Bonding mode 0 to 6
Mode 0 is default - Round Robin
     1 is active-backup   - uses only one interface and second keeps inactive only use the second in case of issue
	 2 is XOR - every transfer when start to use interface will use all packets to send with the same interface depends on the target mentioned jnt he packets
	 3 is broadcast - all data to all interfaces 
     4 is IEEE 802.3ad - can help increase network transfer rates 
	 5 is adaptive transmit load balancing  - will send the data to the interface which less busy 
	 6 is adaptive load balancing - trying to load balance both INCOMING and OUTCOMING trafics between both interfaces
	 
	 
	 
Bridge - connect two ore more networks together and act like one network
Bond - two or more connection to the network

///////////////////////////BOND ///////////////////////


If your goal is reliability or speed, choose bonding.
If your goal is connecting multiple interfaces or VMs into one LAN, choose bridging.

Bonding combines multiple network interfaces into one for redundancy or throughput, while bridging connects interfaces so devices on different segments behave as if they’re on the same Layer‑2 network.

What each one does
Bond (Link Aggregation / NIC Bonding) — Multiple physical NICs are merged into one logical interface. The goals are redundancy, failover, and sometimes higher throughput, depending on the bonding mode. 

Bridge (Layer‑2 Switch) — A virtual switch that connects two or more interfaces so all devices appear to be on the same LAN segment. No routing; it’s pure Layer‑2 forwarding.
