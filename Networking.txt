Configure IPv4 and IPv6 networking and hostname resolution

>ip link - to see internet interfaces (network devices)

>ip address - to see ip addresses configured to these INTERFACES 
>ip ddr OR ip a  - the same

to add color to the output:
>ip -c addr  

To bring internet interface UP :
>sudo ip link set dev enp0s8 up  - with link set device enp0s8 to UP

To add ipv4 to the interface:
>sudo ip addr add 10.0.0.40/24 dev enp0s8
>sudo set ip addr add fe80::5054:ff:fe1f:8050/64 dev enp0s8   - to set IPv6 ip address

Remove ip address:
sudo ip addr delete fe80::5054:ff:fe1f:8050/64 dev enp0s8

Down the interface:
>sudo ip link set dev enp9s8 down

When we done with configuration run:
>sudo netplan try
>ip route - check the routes

	
Those two lines define the DNS servers your system will use for name resolution. They tell Netplan to configure the interface to use 8.8.8.8 and 8.8.4.4 as DNS servers.	
Netplan writes these DNS servers into the backend resolver. You can verify with:
>resolvectl status
or check /etc/resolv.conf depending on your system. 


This means:

The destination network is 192.168.0.0/24  
(all IPs from 192.168.0.1 to 192.168.0.254)

To reach that network, your machine should send packets to the gateway 10.0.0.100.

In other words:

“If you want to reach any device in 192.168.0.x, forward the traffic to 10.0.0.100.”

This is a static route—useful when that network is behind another router.

- to: default
  via: 10.0.0.1
  
  is defines the default gateway.

to: default means “all traffic that doesn’t match any other route.”

via: 10.0.0.1 means “send it to 10.0.0.1.”

This is your internet gateway.

So:

“For everything else (web browsing, external networks), send traffic to 10.0.0.1.”


Destination	How traffic is routed
192.168.0.0/24	Forward to 10.0.0.100
Anything else	Forward to 10.0.0.1 (default route)
