>sudo vim /usr/local/bin/binmyapp.sh - create a script for the app

#!/bin/bash

echo "My App been started" | systemd-cat -t MyApp -p info #systemd-cat is utility which recieves messages and logs it , -t - adds identy to the log so we know the message belongs to the MyApp, -p sets the priority of the message to info
sleep 5 #wait fot 5 seconds 
echo "My App been crashed" | systemd-cat -t MyApp -p err 	 

Make the file executable:

>sudo chmod +x /usr/local/binmyapp.sh 

How to create a SYSTEMD service ?
we can look at MAN
>man systemd.service
and write /EXAMPLES to see what is the base file structure

To see all existing systemd files already in the system:
>ls /lib/systemd/system 

For example we can copy the service SSH Daemon and modify it for our app:
>sudo cp lib/systemd/system/ssh.service /etc/systemd/system/myapp.service 

and now we can adit it:
>sudo vim /etc/systemd/system/myapp.service  - tree parts it will have Unit,Service,Install
In Unit part you can see:
After = which says to run this service after services which is mentioned in this line
ConditionPathExist = ! - says start the file only if this file is not exist
In Service part:
Environment - loads ENV variables listed int the file
ExecStartPre - we can specify a program that should run before our appl will be launched
so we can put :ExecStartPre=echo "systemd is preparing to start MyApp"
ExecStart - path to the script: 
ExecStart=/usr/local/bin/binmyapp.sh
KillMode=process - says kill only this process and not any child  ,use KillMode=control-group - to kill any process created by this service
Restart=on-failure - restart our app when it fails.When app exist 0 good and >0 is has an error 
Restart=always 
RestartSec=1 - will restarted with delay 1 second 
Type=notify - will notify when it started (in our case we do not have kind of this capability).oneshot - when program that quickly opens ,do some deletion and then exits because nothing to do.Type=working - option that spawns many chid processes when it's executed
Type=simple

WantedBy=multi-user.target - is to start multi user (no graphical)
So in our case we say this service (our MyApp) belongs to the multi-user.target group 
Alias=sshd.service - instruct systemd to create links to our .service file in another locations
