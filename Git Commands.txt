>git restore <filename>  - when file was staged first and then modified , we want to back to the file stage when it was staged (so without new modification)



>git restore --stage  - for exaple when we have 2 or more files in the staging area but we do not want to commit a both , only one we want to commit.So the command can help us to remove the file from staging area back to be in WOrking Area - Modified


Action	Command	Effect
Undo file changes	git restore file	Reverts file to last commit
Unstage a file	git restore --staged file	Keeps changes, removes from staging
Restore from commit	git restore --source <hash> file	Pulls file from older commit
Undo all changes	git restore .	Resets entire working directory

Remove /Delete the file:

git rm — remove a tracked file from the repo
git rm means:

“Delete this file from my working directory AND from the Git repository.”

It affects:

your working directory

the staging area

the next commit

git rm config.txt
git commit -m "Remove config file"


Result:

config.txt is deleted from disk

Git marks it as removed

It disappears from the repo in the next commit

///////////////////////////Git Merge ///////////

1)When work done on the feature branch do checkout to the branch which you wat get the merge
for example i have worked on feature_1 branch and now want merge to master - so need first CHECKOUT TO THE MASTER

>git checkout master
>git merge feature_1   - now we merge feature_1 to the master branch 


Two types of merge: fast-forward and no-fast-forward 

fast-forward happens when master banch does not have any commit since we created our feature bracnh - so it will just like cpu our commits without changing them - NO NEW MERGE COMMIT WILL BE CREATED (no need)

no-fast-forward - happens when master branch has commits which creaeted after the feature branch created (so files modified in the master branch) - so new MERGE COMMIT WILL BE CREATED
