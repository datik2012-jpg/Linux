When we install Ubuntu - SWAP and file will be set by default

To do it manually(create a swap file) we need create a next file with binary zero filled:

sudo dd if=/dev/zero of=/swap bs=1M count=128

This creates a 128 MB swap file filled with zeros.

Here’s the meaning of each part:

sudo
Runs the command with administrator privileges.

dd
A low‑level copying tool used to write raw data to files or devices.

if=/dev/zero
if = input file

/dev/zero is a special file that outputs infinite zeros

So you’re writing zeros into the new file

of=/swap
of = output file

This creates a file named /swap in the root directory

bs=1M
Block size = 1 megabyte

Each block written is 1 MB

count=128
Write 128 blocks

128 × 1 MB = 128 MB swap file

What happens next (normally)
After creating the file, you would:

Set correct permissions

Code
sudo chmod 600 /swap  - only root user can read and write to this swap file
Format it as swap

Code
sudo mkswap /swap
Enable it

check the swap active areas again:
>sudo swapon --verbose /swap

swapon --show 

Code
sudo swapon /swap
Make it permanent in /etc/fstab

Code
/swap   none   swap   sw   0  0



Another command wil show us the progress during creation a swap file:

sudo dd if=/dev/zero of=/swap bs=1M count=2048 status=progress

-i size=512 — sets the inode size to 512 bytes (default is usually 256). Larger inodes can store more extended attributes, useful for systems with heavy metadata usage.

An inode (short for index node) is a fundamental data structure used by many Unix‑like file systems—including XFS, ext4, and others—to store metadata about a file.



Force formating :

>sudo vim /etc/fstab

/dev/vdb3    none    swap    defaults    0    0

/etc/fstab — the file that defines which disks and partitions are mounted automatically at boot, and where they’re mounted.

What it means
/dev/vdb3 — the device that will be used for swap.

none — no mount point, because swap isn’t part of the filesystem hierarchy.

swap — specifies the filesystem type as swap space.

defaults — uses standard mount options.

0 0 — disables dump and fsck checks (swap doesn’t need them).


Why it’s important
Swap acts as virtual memory, extending RAM by using disk space when physical memory runs low. It helps prevent out‑of‑memory crashes and keeps the system responsive under heavy load.

-o allocsize=32K — sets the allocation size for the filesystem to 32 KB. This option is specific to XFS and controls the default block size used for file allocation, which can affect performance for workloads with many small or large files.

XFS will preallocate 32 KB chunks whenever a file is extended.
For example:

If an application writes 4 KB at a time, XFS still reserves 32 KB on disk.

The next writes fill that reserved space without needing new allocations.

This reduces overhead from constant extent management and keeps files more contiguous.

Choosing the right value
Small files / random writes: smaller allocsize (e.g., 8K–32K) avoids wasted space.

Large sequential writes (backups, media): larger allocsize (e.g., 256K–1M) improves throughput.

SSD storage: moderate values (64K–128K) balance speed and space efficiency.

NOtes for me:


Option	Description
/etc	The directory being exported via NFS.
127.0.0.1	The client allowed to access it — the local machine itself.
sync	Data is written to disk before replies are sent (safer).
wdelay	The server may delay writes slightly to combine operations for efficiency.
hide	Prevents clients from seeing sub-exports within this directory.
no_subtree_check	Skips subtree verification for performance and fewer permission issues.
sec=sys	Uses standard UNIX authentication (UID/GID).
ro	Read-only access.
secure	Requires requests from ports below 1024 (traditional security measure).
root_squash	Maps remote root user to a non-privileged user (prevents root access).
no_all_squash	Keeps normal users’ UIDs/GIDs intact (only root is squashed).

So root_squash “squashes” that remote root user:

It maps remote root (UID 0) to a non‑privileged user, usually nobody or nfsnobody.

This means remote root can’t change ownership or permissions on server files.

It’s a security measure — prevents root access from clients.

This controls how non‑root users are handled.

With no_all_squash (the default), only root is squashed — all other users keep their real UID/GID.

With all_squash, every remote user is mapped to nobody, regardless of UID.

That way:

Normal users can work normally.

Remote root can’t take over your server.
