When we install Ubuntu - SWAP and file will be set by default

To do it manually(create a swap file) we need create a next file with binary zero filled:

sudo dd if=/dev/zero of=/swap bs=1M count=128

This creates a 128 MB swap file filled with zeros.

Here’s the meaning of each part:

sudo
Runs the command with administrator privileges.

dd
A low‑level copying tool used to write raw data to files or devices.

if=/dev/zero
if = input file

/dev/zero is a special file that outputs infinite zeros

So you’re writing zeros into the new file

of=/swap
of = output file

This creates a file named /swap in the root directory

bs=1M
Block size = 1 megabyte

Each block written is 1 MB

count=128
Write 128 blocks

128 × 1 MB = 128 MB swap file

What happens next (normally)
After creating the file, you would:

Set correct permissions

Code
sudo chmod 600 /swap  - only root user can read and write to this swap file
Format it as swap

Code
sudo mkswap /swap
Enable it

check the swap active areas again:
>sudo swapon --verbose /swap

swapon --show 

Code
sudo swapon /swap
Make it permanent in /etc/fstab

Code
/swap   none   swap   sw   0  0



Another command wil show us the progress during creation a swap file:

sudo dd if=/dev/zero of=/swap bs=1M count=2048 status=progress

-i size=512 — sets the inode size to 512 bytes (default is usually 256). Larger inodes can store more extended attributes, useful for systems with heavy metadata usage.

An inode (short for index node) is a fundamental data structure used by many Unix‑like file systems—including XFS, ext4, and others—to store metadata about a file.



Force formating :
sudo mkfs.xfs -f -i size=512 /dev/sdb1

-f (force) — forces the creation even if the partition already contains a file system or appears to be in use. This bypasses safety checks, so it should be used only when you’re absolutely sure you want to overwrite existing data.

//////////////////// SWAP configuration /////////

>sudo vim /etc/fstab

/dev/vdb3    none    swap    defaults    0    0

/etc/fstab — the file that defines which disks and partitions are mounted automatically at boot, and where they’re mounted.

What it means
/dev/vdb3 — the device that will be used for swap.

none — no mount point, because swap isn’t part of the filesystem hierarchy.

swap — specifies the filesystem type as swap space.

defaults — uses standard mount options.

0 0 — disables dump and fsck checks (swap doesn’t need them).


Why it’s important
Swap acts as virtual memory, extending RAM by using disk space when physical memory runs low. It helps prevent out‑of‑memory crashes and keeps the system responsive under heavy load.

0 1 — tells fsck to check this partition first at boot.

-o allocsize=32K — sets the allocation size for the filesystem to 32 KB. This option is specific to XFS and controls the default block size used for file allocation, which can affect performance for workloads with many small or large files.

XFS will preallocate 32 KB chunks whenever a file is extended.
For example:

If an application writes 4 KB at a time, XFS still reserves 32 KB on disk.

The next writes fill that reserved space without needing new allocations.

This reduces overhead from constant extent management and keeps files more contiguous.

Choosing the right value
Small files / random writes: smaller allocsize (e.g., 8K–32K) avoids wasted space.

Large sequential writes (backups, media): larger allocsize (e.g., 256K–1M) improves throughput.

SSD storage: moderate values (64K–128K) balance speed and space efficiency.

Option	Description
/etc	The directory being exported via NFS.
127.0.0.1	The client allowed to access it — the local machine itself.
sync	Data is written to disk before replies are sent (safer).
wdelay	The server may delay writes slightly to combine operations for efficiency.
hide	Prevents clients from seeing sub-exports within this directory.
no_subtree_check	Skips subtree verification for performance and fewer permission issues.
sec=sys	Uses standard UNIX authentication (UID/GID).
ro	Read-only access.
secure	Requires requests from ports below 1024 (traditional security measure).
root_squash	Maps remote root user to a non-privileged user (prevents root access).
no_all_squash	Keeps normal users’ UIDs/GIDs intact (only root is squashed).

So root_squash “squashes” that remote root user:

It maps remote root (UID 0) to a non‑privileged user, usually nobody or nfsnobody.

This means remote root can’t change ownership or permissions on server files.

It’s a security measure — prevents root access from clients.

This controls how non‑root users are handled.

With no_all_squash (the default), only root is squashed — all other users keep their real UID/GID.

With all_squash, every remote user is mapped to nobody, regardless of UID.

That way:

Normal users can work normally.

Remote root can’t take over your server.

/dev/nbd0 is a Network Block Device (NBD) interface in Linux — it allows one server to use a remote disk as if it were a local block device. In the diagram, Server 1 accesses a disk from Server 2 over the network through this NBD connection, effectively mounting Server 2’s /dev/vda as /dev/nbd0 on Server 1.

Device file: /dev/nbd0 is the first NBD device created by the kernel module nbd.

Function: It acts as a proxy block device — data read/writes on /dev/nbd0 are transmitted over TCP/IP to a remote NBD server process.

Usage: Commonly used for remote storage, disk mirroring, or testing distributed block systems.

Analogy: Think of it like mounting a remote hard drive over the network, similar to how NFS mounts filesystems, but at the block level rather than the file level.

Mimic :

dd if=/dev/zero of=DELETEME bs=1 count=1000000 oflag=dsync &


Part	Meaning
dd	A low-level data copying utility used for writing raw data between files or devices.
if=/dev/zero	Input file — /dev/zero generates continuous null bytes (zeros).
of=DELETEME	Output file — the data will be written into a file named DELETEME.
bs=1	Block size — each write operation handles 1 byte at a time.
count=1000000	Number of blocks — 1,000,000 bytes total (≈1 MB).
oflag=dsync	Forces synchronous writes — ensures each write is physically committed to disk before continuing.
&	Runs the command in the background, freeing the terminal for other tasks.


This command creates a 1 MB file filled with zeros, named DELETEME, and writes it synchronously to disk. Because of dsync, it’s slower but ensures data integrity — useful for testing disk performance or simulating write load.

sudo sh -c 'echo "This is the file content" > file3'

We can see alex is the owner at the moment:
ls -l file3
-rw-rw-r-- 1 alex staff 25 May 23 06:18 file3

User dani can not write to that file bt can read.

ACL can help us with providing more general permission like DANI can WRITE and READ ,Jane can READ, ALEX can WRITE and Execute:

Need to install ACL first:
>sudo apt install acl 

to add the user to ACL:

>sudo setfacl --modify user:jeremy:rw file3 - if you want to add all permissions (rwx)

Now if we check ls -l we can see + in the file3 which we added ACL:
total 4
-rw-rw-r--  1 alex staff  0 May 23 05:56 file1
-rw-rw-r--  1 alex staff  0 May 23 05:56 file2
-rw-rw-r--+ 1 alex staff 29 May 23 06:23 file3

How to inspect ACLs

>getfacl file3   - and we can see jeremy get "rw"

# file: file3
user::rw-
user:alex:rw-
user:jeremy:rw-
group::rw-
mask::rw-
other::r--


We do not want  manually to add ACL per user !!It is overkill for us so we can add a MASK.


Mask limits permission to READ only: 

Even though jeremy and staff have rw- permissions in their ACL entries, the mask restricts them to read‑only (r--).
That’s why the output shows #effective:r-- — the mask overrides their write access.

>sudo setfacl --modify mask:r file3
>getfacl file3

# file: file3
# owner: alex
# group: staff
user::rw-
user:jeremy:rw-              #effective:r--
group::rw-                   #effective:r--
mask::r--

To restore write access:
sudo setfacl --modify mask:rw file3

For GROUPS add ACL:
sudo setfacl --modify group:sudo:rw file3

getfacl file3

# file: file3
# owner: alex
# group: staff
user::rw-
group::rw-
group:sudo:rw-
mask::rw-
other::r--

To remove the ACL for specific use:
sudo setfacl --modify user:jeremy:--- file3

or REMOVE from ACL:
sudo setfacl --remove user:jeremy file3

or REMOVE from sudo group:

sudo setfacl --remove group:sudo file3

To remove all ACL entries:
sudo setfacl --remove-all file3


To applly ACL to directory need to do it RECURSIVERY and when need RECURSEVLY to remove as well for the group:
mkdir dir1
setfacl --recursive -m user:jeremy:rwx dir1/


/////////////////Allow to add only new content to the file BUT not allowing to delete the current content ////
sudo chattr +a newfile   - append only 
Once set, the file cannot be overwritten or deleted — only appended to.

to remove the APPEND to the file:
>sudo chattr -a newfile

File can not be renamed ,deleted or edited - mkaes the file immutable:
>sudo chattr +i myfilename 


To check the attr:
>lsattr myfile 
----i--------e------- newfile

or for entire directory list file attributes:

>lsattr 

-----------------e------- ./file3
-----------------e------- ./file2
-----------------i------- ./newfile
-----------------e------- ./dir1

To remove the attribute:
sudo chattr -i newfile
