Identity a service :

or Search for a service by keyword:

systemctl list-units --type=service | grep <keyword>

Find processes related to a service:

ps aux | grep <name> 

Check the Service Status

systemctl status <service-name>

Log Analyzing View logs for a specific service

journalctl -u <service-name>

View only recent logs

journalctl -u <service-name> -n 50

Follow logs in real time

journalctl -u <service-name> -f

Look for errors

journalctl -u <service-name> | grep -i error

Identify the Root Cause:

A. Configuration Errors
Missing config files

Wrong permissions

Syntax errors

sudo cat /etc/<service>/<config-file>
sudo ls -l /etc/<service>/

B. Port Conflicts

sudo lsof -i -P -n | grep LISTEN

C. Dependency Failures

systemctl list-dependencies <service-name>

D. Resource Issues
Out of memory

Disk full

CPU overload

df -h
free -h
top

E. SELinux / AppArmor Blocking

sudo ausearch -m avc
sudo dmesg | grep DENIED



Check system-wide failures:

systemctl --failed

Detect Which Process Is Failing Right Now

A. Use top or htop


B. Check for rapidly restarting services
bash

systemctl --failed
systemctl list-units --type=service

C. Watch the system log live

journalctl -f

If You Only Know the Port or Behavior
A. If the program listens on a port

sudo lsof -i -P -n | grep LISTEN

If it writes files

sudo lsof | grep <filename>

C. If it uses a specific directory

sudo lsof +D /path/to/directory

Once You Identify the Process, Find the Service
If you found a PID:

ps -p <PID> -o comm=
systemctl status <process-name>

Analyze the Root Cause

journalctl -u <service>

As you can see two disks:
vde and vdf are empty disks at the moment.No FSTYPE,NO UUID , no MOUNTPOIN - so no partition ,no file system ,no mounted ,

The easier way to use the disk without any partition and create Filesystem:
Run this > sudo mkfs.ext4 /dev/vde 
and now if we check again the disks:
>lsblk -f
we will see the disk get ID:
vde   ext4   478525e5-3804-4ba8-9719-bd636366dfas

Now need mount a disk to some folder (need create a folder first> sudo mkdir -p /mnt/data):

and only now we can nount a disk to the folder:
>sudo mount /dev/vde /mnt/data

so now /mnt/data will be our new DISK

Check:
>df -h | grep vde

For make the disk be automatic connected during the BOOT system:

check the disk ID:
>blkid /dev/vde
Output: /dev/vde: UUID="abcd-1234" TYPE="ext4"

add to /etc/fstab - here Linux keep the list of disks which should be automatic mounetd during a boot:
example:UUID=abcd-1234   /mnt/data   ext4   defaults   0   2

Validation if we are good (if no errors):

sudo umount /mnt/data
sudo mount -a
